## Step-by-Step Migration Plan (One File at a Time)

### Safety Protocol
Before each file migration:
1. **Pre-check**: Verify source file exists, is readable, and `md5sum` matches expected hash
2. **Backup**: Copy source file to `/tmp/opencode/audio-backup/<filename>.<timestamp>.bak` (timestamped, never destructive)
3. **Copy** to dotfiles location (if not already there)
4. **Verify copy**: `md5sum` comparison between source and destination
5. **Remove** original file (only after copy verification passes)
6. **Create symlink**: `ln -s <dotfiles_path> <original_path>`
7. **Verify symlink**: `readlink` + `md5sum` through the symlink matches
8. **Service restart/reload** if affected (see per-file notes below)
9. **Functional verification** (see section below)

### File Groups (migrate top-to-bottom)

**Group 1: PipeWire configs** (no service restart needed — PipeWire picks up changes from config dir on restart)
- A1, A2

**Group 2: WirePlumber conf.d** (may need `systemctl --user restart wireplumber` after all 3)
- B1, B2, B3

**Group 3: WirePlumber filter-chains + docs** (no restart needed — only loaded when device connects)
- C1–C6

**Group 4: Scripts** (need `chmod +x` preserved on dotfiles copy; existing `~/.local/bin/` symlinks already follow this pattern)
- D1, D2, D3

**Group 5: Systemd services** (2 service files already exist in dotfiles — just replace `~/.config/` copies with symlinks; then `systemctl --user daemon-reload`)
- E1, E2

**Group 6: XDG autostart** (no restart needed — read at next login; existing enablement already handled by systemctl)
- F1, F2

## Risk Assessment
- **Low risk**: Config files are read at runtime from XDG dirs; symlinks are transparent to all consumers
- **Mitigated**: Backups stored in `/tmp/opencode/audio-backup/` for every file
- **Reversible**: Each symlink can be removed and original file restored from backup in one command
- **Already-in-git files (E1/E2)**: Only need symlink replacement, no content transfer — safest operation
